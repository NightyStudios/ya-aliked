# urban3d_eval — MMA / MHA на Urban3D

Бенчмарк методов поиска ключевых точек и матчинга из репозитория на датасете
Urban3D (исходный тайл ↔ его аугментированные варианты с плотной геометрической
разметкой соответствий).

| Файл | Назначение |
|---|---|
| `dataset.py` | поиск тайлов, пары `source.png` ↔ `aug_XX/image.png`, плотные GT через декодер самого датасета |
| `extractors.py` | методы: ORB/SIFT/XFeat из реестра демо (`demo/backend/app/registry.py`), ALIKE из ветки FIR |
| `metrics.py` | MMA / MHA по плотной GT |
| `evaluate.py` | прогон, построчная запись в `results/per_pair.jsonl` (возобновляемый) |
| `report.py` | `results/results.md`, `summary.csv`, `per_pair.csv` из `per_pair.jsonl` |
| `tests/` | юнит-тесты метрик |

## Методы

| Метод | Источник | Дескриптор |
|---|---|---|
| `orb_cv` | `cv2.ORB_create` (демо, `orb_cv`) | binary 256, Hamming |
| `orb_manual` | ручной ORB, один масштаб (демо) | binary 256, Hamming |
| `orb_fast` | ручной ORB, векторизованный (демо) | binary 256, Hamming |
| `orb_pyramid` | ручной ORB с пирамидой (демо) | binary 256, Hamming |
| `sift_cv` | `cv2.SIFT_create` (демо, `sift_cv`) | float32 128, L2 |
| `xfeat` | XFeat, CVPR 2024 (демо, `xfeat`) | float32 64, L2 |
| `alike_n`, `alike_l` | ALIKE (ветка `FIR`, веса `models/alike-{n,l}.pth`) | float32 128, L2 |

ALIKED в сравнение не входит: в репозитории только код обучения (ветка `maxb`),
опубликованных весов нет.

Для всех методов одинаково: бюджет `--max-keypoints` (по умолчанию 2000) точек
на изображение, нативное разрешение 2048×2048, один матчер — взаимный ближайший
сосед (`BFMatcher(crossCheck=True)`, Hamming для бинарных, косинус для float),
как в `ORB/metrics/local_feature_metrics.py`. Лоу-ratio и RANSAC-фильтр матчей
не применяются.

## Метрики

Определения совпадают с `ORB/metrics/local_feature_metrics.py` (HPatches); GT
берётся не из одной гомографии, а из плотных соответствий датасета.

* **MMA@t** — доля матчей, у которых точка A, перенесённая GT в B, лежит не
  дальше `t` px от сопоставленной точки B. Матчи, у которых точка A не имеет GT
  (NoData, вне кадра, закрыта поверхностью в B), не оцениваются; их доля в
  отчёте — «matches with GT». GT в дробной точке — билинейная интерполяция
  `forward_xy` по видимым пикселям.
* **MHA@t** — доля из 4 углов изображения A, чья позиция под гомографией,
  оценённой по матчам (RANSAC, порог 3 px), отличается от позиции под
  опорной гомографией не больше чем на `t` px.
* **Опорная гомография** — RANSAC (порог 3 px) по сетке видимых GT-соответствий
  (шаг 8 px). Сцена трёхмерная (крыши, наклон до ±20°), точной гомографии нет:
  это гомография доминирующей плоскости. Доля инлаеров опорной H записана для
  каждой пары (`reference_inlier_ratio` в `per_pair.csv`).
* Пары с < 4 матчами дают MHA = 0, без матчей MMA = 0.
* Итоговое значение — среднее по парам (macro), доли в [0, 1], t = 1…5 px.

## Запуск

Из корня репозитория. Зависимости: `numpy`, `opencv-python-headless`; для XFeat
и ALIKE — `torch`, `torchvision`, `tqdm`; для компиляции декодера датасета —
`c++` (C++17).

```bash
# распаковать архивы Urban3D в отдельные папки
mkdir -p ~/urban3d/part_02 ~/urban3d/part_03
unzip -q urban3d_part_02_of_03.zip -d ~/urban3d/part_02
unzip -q urban3d_part_03_of_03.zip -d ~/urban3d/part_03

# XFeat (код + веса) и ветка FIR (код ALIKE + веса)
git clone --depth 1 https://github.com/verlab/accelerated_features.git ~/accelerated_features
git archive origin/FIR | tar -x -C ~/ya-aliked-fir     # предварительно mkdir

python -m urban3d_eval.evaluate --data ~/urban3d \
    --xfeat-dir ~/accelerated_features --alike-dir ~/ya-aliked-fir
python -m urban3d_eval.report
python -m unittest urban3d_eval.tests.test_metrics
```

`--data` принимает корни датасета (папка с `tiles/`) или папки, в которых они
лежат; сколько частей `urban3d_part_*` подано — столько и считается.
`--methods` ограничивает набор методов, `--limit-tiles` — число тайлов.
Повторный запуск продолжает с того места, где остановился.

Что учитывать при чтении цифр:

* В выборке нет `urban3d_part_01` (его не было среди присланных архивов), поэтому
  53 тайла из 79. `--data` примет и эту часть, достаточно положить её рядом.
* MHA считается относительно гомографии доминирующей плоскости 3D-сцены, а не
  точной гомографии (см. «Метрики»): на парах с большим наклоном (≥ 14°) часть
  ошибки — это параллакс крыш, а не ошибка метода. Для сравнения методов между
  собой это одинаково для всех.
* `ms / image` в `results.md` измерены в параллельном прогоне на CPU и завышены
  (особенно у ALIKE); сравнивать их можно только внутри таблицы.
* XFeat даёт низкий MMA (медианная ошибка матча ~4–6 px) из-за того, что его
  детектор не инвариантен к сдвигу на величину, не кратную 8 px (ячейки 8×8
  карты ключевых точек). Проверено на одном тайле, одно и то же изображение,
  сдвинутое без передискретизации и шума: сдвиг на 8 или 16 px — MMA@3 = 0.99;
  сдвиг на (4, 4) — MMA@3 = 0.32, медиана ошибки 6 px, повторяемость точек
  (1 px) 0.12; у SIFT при тех же сдвигах MMA@3 = 1.00. Поворот и наклон в
  Urban3D сдвигают точки на произвольные дробные величины, поэтому ячейки
  не совпадают. На чистом сдвиге на 8·k px XFeat работает на уровне SIFT, масштаб
  входа (2048 / 1024 / 512) на результат не влияет. Это свойство метода, а не
  ошибка интеграции: используется код и веса verlab/accelerated_features.
* Матчинг один для всех методов (mutual NN). Родные матчеры (например LightGlue
  для XFeat) не использовались.

Данные: Vricon / USSOCOM Urban3D (SpaceNet), некоммерческая лицензия; архивы
в репозиторий не входят.
